# Design v2.1: deltas from the v2.0 specification

The v2.0 spec (`v2.0-en.md`) remains the baseline. These are the deliberate changes made for
Stage 1; each links to an ADR where the reasoning is longer.

| v2.0 | v2.1 (Stage 1) | Why |
|---|---|---|
| Vite SPA + Vercel `api/gateway.ts` | Next.js 16 App Router; gateway is `app/api/v1/[...path]/route.ts` | Product decision ([ADR 0001](../adr/0001-nextjs-app-router.md)); same `/api/v1` contract, JSON 404s |
| Implicit-flow SPA auth, Bearer token | `@supabase/ssr` cookie sessions; magic link via `token_hash` → `/auth/confirm`; Google via PKCE → `/auth/callback`; every API call still validated with `getUser()` | Next.js SSR needs cookies; `token_hash` survives opening the mail in another browser |
| Invite-only (`shouldCreateUser:false`) | Open sign-up | Product decision for the hackathon |
| Gateway → Azure → LLM | `AI_EXECUTION=direct`: route handlers call Gemini in-process; `relay` forwards to FastAPI later | No backend in Stage 1 ([ADR 0004](../adr/0004-direct-ai-execution.md)) |
| AI-R returns MathJSON | Flat JSON with LaTeX per segment, parsed into IR by our deterministic parser | Structured output cannot reliably express the recursive IR; LaTeX transcription is more reliable ([ADR 0002](../adr/0002-latex-wire-format.md)) |
| Temperature 0 | `thinking_level` per task | Current Gemini API |
| Only CAS-ok candidates shown | ok / none / unknown candidates shown with distinct styles; unknown needs a second confirmation; wrong never adoptable, surfaced as a "checker rejected" chip | Physics steps often exceed the CAS ([ADR 0003](../adr/0003-candidate-policy.md)) |
| Textbooks are Could (C-02) | Resources tab is core; stored in Supabase (Storage bucket + tables), cached on the device; feeds suggestion context (≤ 9000 chars) | Product vision; cross-device ([ADR 0005](../adr/0005-cloud-sync.md)) |
| Manual save (M-11), optional autosave (S-06) | Autosave always on, no Save button; outbox + recovery as copy; ink stored by hash beside the snapshot; account settings in `mn_user_settings` | [ADR 0005](../adr/0005-cloud-sync.md) |
| No automatic suggestions | Suggestion requested after a line settles and the writer pauses; adoption stays explicit | Cursor-like UX; P-03 unchanged |
| Real algebra/calculus only | Physics profile: multi-argument functions, ∂, definition substitution, nonzero scaling, separation constants, ODE solution checks, `E_n` aliases | Demo derivation |
| `Problem` without functions | `Problem.functions: {name, args}[]` | Disambiguates `ψ(x)` (application) vs `a(x)` (product) |
| `Assumption.symbol` only | `Assumption.expr` for `nonzero` assumptions such as ψ(x) ≠ 0 | Needed to divide by ψφ |
| IR operators | `PartialD`; `Apply` with 0–4 arguments (0 = declared arguments, written as a bare ψ); `Prime` wraps an `Apply` with an order; unary `PlusMinus` | Faithful display of physics notation |
| Methods | adds `scale`, `sep`, `sub` | New goals |
| Reasons | adds `SUBSET_OF_SOLUTIONS` | Honest status for e.g. kL = nπ |
| `SuggestInput` | adds `rejected_latex`, `demo` binding; `RecognizeInput` adds `user_line_index`, `demo` | Avoid repeats; scripted demo |
| Mock mode = zero external calls | Demo notebook = live recognition + scripted suggestions, labelled "Demo · scripted AI" | Demo choice |
| `VITE_*` env, Vite feature registry | `NEXT_PUBLIC_*`; registry generated before dev/build | Next.js |
| Vitest | Node test runner (`tsx --test`) + Playwright | No Vite in the stack |
| M-10 `.tex` source download, with LuaLaTeX used in output tests | Current PDF export runs in the browser via KaTeX → page images → PDF; no Azure or TeX runtime | User-directed prototype scope ([ADR 0005](../adr/0005-browser-pdf-export.md)); text selection/search is deferred |
| S-05 Lean: separate Proof panel, confirmed `FormalExpr` task, structured plan compiler | The model routes each line (`cas`/`lean`/`none`); Lean checks proof lines in the notebook, one tactic per line, in a separate lean-worker service; raw tactics screened instead of a plan language; Lean-checked suggestions; two proof templates | Product direction: CAS for algebra, Lean for proofs in words ([ADR 0008](../adr/0008-lean-proof-checking.md)) |
| REJECT_CANDIDATE in history | Rejection is not an undoable command in Stage 1 | Simplification; rejection changes no line |
